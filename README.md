# Stock Signal

미국장 종가 기준으로 **지금의 시장 상태**와 **규칙상 목표 비중**을 보여주는 개인용 대시보드입니다.
자동 주문·계좌 연동·실제 보유 비중 추적은 없습니다. 외부 데이터 API 키를 발급받지 않고 사용합니다.

## 사이트

https://stocksignal-psi.vercel.app

## 로컬 실행

Python 3.11 이상을 설치한 Windows에서 이 폴더의 `update.ps1`을 PowerShell로 실행합니다.
처음에는 가상환경과 필요한 패키지를 설치합니다. 현재 가상환경이 있으면 그대로 사용합니다.

```powershell
.\update.ps1
```

완료 후 `site/index.html`을 브라우저로 열면 됩니다. 인터넷 없이 저장된 결과를 열 수 있지만, 새 데이터 수집에는 인터넷이 필요합니다.
브라우저에서 새로고침하는 것은 수집 요청이 아닙니다. 갱신 스크립트를 실행한 후 새로고침해야 새 결과가 보입니다.

```powershell
# 저장된 데이터만 다시 화면으로 만들기
.\.venv\Scripts\python.exe -m stock_signal.app --build-only
# 경계값, 상태 유지, 선행정보 방지, 누락·오류 보존, 휴장·조기폐장 테스트
.\.venv\Scripts\python.exe -m pytest -q
```

## 전략 기본값

- 기준: Nasdaq-100 `^NDX` 비수정 종가. 매매 대상 ETF 가격으로 신호를 대체하지 않습니다.
- 250거래일 단순이동평균, VIX 종가 10거래일 단순평균, 당일 포함.
- 52주 고점 = 최근 252거래일 최고 종가.
- NDX > MA250 × 1.01: 상승. NDX < MA250 × 0.95: 하락. 경계 포함 사이 구간: 이전 시장 유지.
- 상승, VIX10 < 28, 현재 낙폭 ≤ 9%: TQQQ 100%.
- 상승, VIX10 ≥ 28 또는 낙폭 > 9%: QQQ 50% + QLD 50%.
- 하락, VIX10 < 18: QQQ 50% + QLD 50%. 그 외 하락: 현금 100%.
- 목표가 같으면 변경 없음. 실제 계좌의 가격 변동에 따른 매일 리밸런싱을 요구하지 않습니다.
- 종가 기준일 다음 거래일을 적용 거래일로 표시합니다. 시가/종가 체결 가격은 가정하거나 추적하지 않습니다.
- `config.json`에 파라미터가 있고, 계산에 쓴 설정은 결과에 함께 보관합니다.

## 데이터·복구

`stock_signal/app.py`가 2000년부터 Yahoo Finance NDX와 Cboe VIX의 일별 종가를 읽고 전체 순서를 다시 계산합니다.
실제 확인한 Cboe CSV에는 1991-03-01, 1997-01-31, 1997-11-26, 1999-12-31 자료가 없어, 임의 보간 대신 2000년 이후를 시작점으로 선택했습니다. 35년 백테스트를 재현하는 시작점이 아닙니다.
데이터량이 작아 단순한 전체 재계산을 채택했습니다. 어제 상태를 임의로 정하지 않고 첫 확정 상태부터 순서대로 복원하므로, 중간 실행이 빠져도 다음 성공 시 복구됩니다.
원천 데이터가 과거 수치를 수정하면 과거 신호도 달라질 수 있습니다. `data/state.json`은 계산된 과거 지표와 당시 설정을 보관하고, GitHub에 올린 뒤에는 결과 커밋으로 변화 이력을 남길 수 있습니다.

미국 주식 거래일은 exchange_calendars XNYS 달력을 사용합니다. 일반 NASDAQ 주식 거래일과 같은 휴장·조기폐장 일정을 적용하는 선택입니다.
최신 완료 거래일까지 양쪽 데이터에 누락이 없어야 성공합니다. Cboe 최신 종가 게시 지연은 최대 7일의 끝부분에 한해 Yahoo Finance ^VIX 일별 종가로 보완합니다. 최근 공통 5일의 종가가 0.02 이내로 일치해야 하며, 과거 중간 누락은 보완하지 않습니다. 사용 날짜를 결과와 화면에 기록합니다. 두 경로 모두 최신 값이 없거나 값이 일치하지 않으면 이전 결과를 보존합니다. 당일 미완료 봉은 제외하고 최대 3회 시도합니다.
실패하면 `data/state.json`을 덮어쓰지 않고, 이전 데이터를 사용해 오류 표시가 있는 HTML을 생성하며 종료 코드 1을 반환합니다.
화면은 이후 완료 거래일의 폐장 3시간 후에도 새 데이터가 없으면 지연을 표시합니다. 이 시간은 공급자 갱신 여유시간이지 서비스 보장 시간이 아닙니다.

## GitHub 연결 및 자동 실행 설정

원격 저장소는 https://github.com/why-only-english/StockSignal.git 입니다. 사람의 커밋 작성자와 푸시 인증은 why-only-english 계정을 사용합니다. Pages 활성화와 첫 자동 실행은 별도 설정 단계입니다.

1. 원격 저장소: `why-only-english/StockSignal`.
2. 로컬 변경은 사용자 승인 후 why-only-english 인증을 확인하고 커밋·푸시합니다. 공개 저장소와 표준 Actions 실행 환경을 전제로 한 무료 구성입니다.
3. 저장소 Settings → Pages → Source를 **GitHub Actions**로 지정합니다.
4. Actions 탭의 **Daily Stock Signal**을 수동 실행하고 사이트 배포를 확인합니다.
5. 이후 기본 브랜치의 `.github/workflows/daily.yml`이 미국 주식시장 실제 폐장 시각의 1시간 후에 수집합니다. 정규장 기준 뉴욕 17:00으로, 한국 시간은 서머타임 기간 다음날 06:00 / 그 외 다음날 07:00입니다. `America/New_York` 시간대로 서머타임을 자동 반영합니다. 조기 폐장일은 뉴욕 14:00 슬롯을 사용하고 휴장일은 수집하지 않습니다. 두 예약 슬롯 중 거래일 달력에 맞는 하나만 수집·게시하며, GitHub 예약 지연이나 준비 시간으로 실제 실행은 늦어질 수 있습니다.

Vercel 배포를 위해 Repository secrets에 VERCEL_TOKEN, VERCEL_ORG_ID, VERCEL_PROJECT_ID를 등록합니다. 같은 실행에서 GitHub Pages와 Vercel에 결과를 게시합니다. Vercel 배포 전 계정·팀·프로젝트와 Hobby 플랜을 검증하며, 불일치하면 배포를 중단합니다. 토큰이 만료되면 Secret을 갱신해야 합니다.

워크플로에는 미래 운영을 위한 `git commit`/`git push` 단계가 들어 있지만, 로컬 구현 중에는 실행하지 않았습니다.
이 단계는 성공한 결과 파일 `data/state.json` 하나만 기록합니다. 공급자 장애 시 이전 결과와 오류 상태를 게시한 다음 Actions를 실패로 표시합니다.
브랜치 보호 정책이 봇의 결과 푸시를 막는 저장소에서는 정책에 맞게 기록 방식을 조정해야 합니다.

폴더에 원래 있던 다른 HTML·이미지는 `.gitignore`의 허용 목록으로 제외했습니다. 최초 업로드 때도 전체 폴더를 수동 업로드하지 말고 앱 파일만 선택해야 합니다.
공개 범위는 코드와 산출 신호입니다. 원본 시세 전체를 별도 파일로 게시하지 않습니다. 외부 데이터 이용·공개 범위는 해당 제공자의 조건을 따릅니다.

## 세후 평가액 비교

QQQ·QLD·TQQQ 계속 보유와 전략 전환을 최초 1,000만 원, 추가 입금 없이 비교합니다. 2010-02-11부터 실제 ETF 가격·배당·원/달러 환율을 사용하며, 매 거래일의 세후 평가액을 그래프로 표시합니다. 범례 버튼으로 선을 선택하고 날짜 슬라이더로 네 금액을 조회할 수 있습니다. 목표 변경 이력에는 같은 날짜의 금액(만 원)을 표시하며 비교 시작 전은 `—`입니다.

`stock_signal/comparison.py`가 비교를 계산하고 `data/comparison.json`에 결과를 보관합니다. 매일 신호 수집 후 함께 갱신합니다. ETF 거래일 누락이나 환율 지연 등 비교 데이터 오류가 있으면 이전 비교를 유지하고 화면에 지연을 표시하며, Actions는 게시 후 실패로 표시합니다. 신호 계산과 이메일 알림은 별도로 유지합니다.

- 전날 신호로 다음 거래일 종가에 전환합니다. 목표가 같으면 기존 비중을 매일 재조정하지 않습니다.
- 현재 한국 일반 해외주식 계좌 세금 가정을 전 기간에 적용합니다. 연간 실현손익에서 250만 원 공제 후 22%, 선입선출·매매일 환율입니다. 다음 해 5월 마지막 미국 거래일에 투자금에서 납부하며 필요시 일부 주식을 매도합니다.
- 각 평가일에 가상 전량 매도 시 미납 세금까지 차감합니다. 가상 청산은 이후 운용에 영향을 주지 않습니다.
- 배당 15% 원천징수 후 배당락일 재투자, 소수점 주식 허용, 달러 현금 이자 0의 근사입니다. 수수료·환전 비용·금융소득 종합과세는 제외합니다. 실제 세후 수익률이 아니며 종합과세 대상 배당 연도는 화면에 표시합니다.
- ETF는 Yahoo Finance의 분할 반영 Close와 배당을 사용하며, 수정 종가 수익률에 배당을 중복 가산하지 않습니다. 환율 휴일 누락은 최대 7일 전의 과거 값만 사용합니다. 실제 세무 신고의 결제일 환율과 차이가 있을 수 있습니다.

## 비공개 이메일 알림

공개 구독 폼 없이 Repository secrets의 수신자에게만 알립니다. Gmail SMTP(SSL 465)가 기본이며, 별도 도메인이나 발송 서비스 가입은 필요하지 않습니다.

- `MAIL_USERNAME`: 사용할 발신 Gmail 주소. 자동으로 다른 계정을 선택하지 않습니다.
- `MAIL_PASSWORD`: 해당 계정에서 발급한 앱 비밀번호. 일반 로그인 비밀번호를 넣지 않습니다.
- `MAIL_TO`: 수신 주소 한 개 또는 쉼표로 구분한 여러 주소.

Gmail 앱 비밀번호는 2단계 인증이 필요하며 계정 정책에 따라 사용이 제한될 수 있습니다. [Google 안내](https://support.google.com/mail/answer/185833?hl=ko).
다른 SMTP 서비스는 Repository variables의 `MAIL_HOST`, `MAIL_PORT`로 지정할 수 있습니다. 이 구현은 암호화된 SMTP SSL 연결을 사용합니다.

세 Secrets가 모두 없으면 알림을 건너뜁니다. 첫 활성화 실행은 현재 신호를 기준으로 초기화하고 메일을 보내지 않습니다. 그 뒤 시장 상태 또는 목표 비중이 바뀌면 알리고, 둘 다 바뀌면 한 통으로 합칩니다. 실행이 여러 날 누락되면 확인하지 못한 변경들을 한 통에 모읍니다. 과거 데이터 정정만으로는 소급 알림하지 않습니다.

수신자들은 서로의 주소를 볼 수 없습니다. 주소·비밀번호는 코드, HTML, 알림 기록에 저장하지 않습니다. `data/notification.json`에는 마지막 확인 날짜·시장·목표만 보관합니다. 발송 실패는 Actions 실패로 표시하고 다음 성공 실행에서 다시 시도합니다. Secrets 추가 후 수동 실행하여 기준점을 초기화하세요. 실제 발송 인증은 첫 발송 시 검증됩니다.

일반 재실행은 저장된 기록으로 중복을 방지합니다. SMTP 접수 직후 프로세스 종료·기록 푸시 실패·일부 수신자 거부처럼 발송과 기록 사이에 문제가 생기면 다음 실행에서 중복될 수 있습니다. SMTP 구조상 정확히 한 번의 도착은 보장하지 않으며, 서버 접수 성공도 수신함 도착을 보장하지 않습니다.

## 파일

- `stock_signal/`: 수집·계산·HTML 생성
