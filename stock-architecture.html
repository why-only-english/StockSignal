02 — 전략 엔진 첨부 이미지의 규칙을 계산 로직으로 표현

STEP A / 시장 상태

종가와 250일 이동평균 비교

종가 > 250일선 × 1.01상승
종가 < 250일선 × 0.95하락
그 사이 · 경계값 포함이전 상태 유지

250일은 거래일 기준. VIX10은 VIX 종가의 최근 10거래일 평균. 단순평균을 구현 기본값으로 제안.

STEP B / 목표 비중

시장 상태 + 변동성 + 낙폭

시장조건목표
상승VIX10 < 28 그리고 낙폭 ≤ 9%TQQQ 100%
상승VIX10 ≥ 28 또는 낙폭 > 9%QQQ 50% + QLD 50%
하락VIX10 < 18QQQ 50% + QLD 50%
하락VIX10 ≥ 18현금 100%

STEP C · 직전 거래일과 목표 비중이 같으면 “변경 없음”. 실제 보유량이나 주문 체결 여부는 추적하지 않는다.

03 — 자료에서 확인한 정의와 남은 세부사항 영상 스크립트 반영 · 불명확한 계산 관례는 별도 기록

01 / 기준 지수

나스닥100 지수 · NDX

영상 20:42에서 나스닥100 지수를 명시한다. 판단 지수는 NDX로 설정하고, 매매 대상은 QQQ·QLD·TQQQ로 구분한다. 데이터 장애 시 QQQ로 자동 대체하지 않는다.

02 / 고점의 기간

최근 52주 고점 대비 현재 낙폭

영상 21:01~21:12에서 최근 52주로 명시한다. 현재 낙폭 = (1 − 종가 ÷ 52주 고점) × 100. 52주를 달력 기준으로 볼지 252거래일로 볼지, 최고 종가와 장중 고가 중 무엇을 쓸지는 확인 필요.

03 / 가격과 재현성

종가 확인 후 다음 거래일 적용

영상 14:40~15:17에 따라 신호일과 적용 거래일을 분리한다. 다음 거래일의 시가·종가 중 실제 집행 가격은 미확정이다. 50:50 비중의 일별 재조정 여부도 백테스트 전에 정의해야 한다.

첫 버전 범위: 데이터 수집 · 상태 계산 · 일별 기록 · 화면 게시. 자동매매, 증권계좌 연동, 메신저 봇, 별도 DB 서버는 범위에 포함하지 않는다.

운영 조건과 확인 자료
  • 최초 GitHub 계정 연결과 Actions·Pages 설정이 필요하다. 실행 시에는 GitHub가 제공하는 자동 토큰을 사용하며, 사용자 발급 데이터 API 키는 사용하지 않는다.
  • 무료 구성은 공개 저장소와 표준 GitHub 실행 환경을 전제로 한다. 공개되는 파일에는 개인 보유내역·계좌 정보를 넣지 않는다.
  • 공개 저장소의 예약 작업은 60일간 저장소 활동이 없으면 비활성화될 수 있다. 일별 결과 커밋을 정상 운영 흐름에 포함한다. 장기 장애는 별도 확인이 필요하다.
  • yfinance는 Yahoo의 공식 지원 도구가 아니므로 데이터 제공 방식 변경에 따른 보수가 발생할 수 있다. 데이터 재배포 조건은 실제 공개 범위를 정할 때 확인한다.
